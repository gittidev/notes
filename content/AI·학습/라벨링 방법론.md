## 결론
- **최종 저장 형식은 픽셀 마스크(PNG, 픽셀값 = 클래스 번호)**. 시맨틱 분할 학습이 바로 읽는 형식이고 면적 계산도 바로 된다.
- **그리는 방법은 폴리곤 + 반자동(SAM/특징 기반) 보조**. 식생처럼 경계가 들쭉날쭉하면 손으로 폴리곤만 그리기엔 시간이 너무 든다.
- 폴리곤(JSON)으로 그려도 마스크로 바꿔 쓴다. 둘은 「저장 형식」의 차이일 뿐 대립 개념이 아니다.

## 방식 비교
| 방식 | 장점 | 단점 | 적합 |
|---|---|---|---|
| 폴리곤 수작업(labelme, CVAT) | 정확, 클래스 경계 명확 | 장당 30~60분, 경계가 복잡하면 더 | 최종 검증용 소량 |
| 브러시 마스크 | 자유로운 경계 | 느리고 일관성 낮음(자동 초안이 없을 때) | 보정용 |
| SAM/SAM2 프롬프트 (CVAT·Label Studio·X-AnyLabeling 내장) | 클릭 몇 번으로 경계 자동 | 질감이 균일한 식생은 과분할, 클래스는 사람이 지정 | **1차 라벨링 주력** |
| 특징 기반 반자동 (DINOv2 + 시드 박스 + 로지스틱 회귀 + SLIC) | 시드 몇 개로 여러 장 일괄 | 시드 품질에 의존, 미세 경계 거침 | 대량 초벌 라벨 |
| 정사영상 위 라벨링(QGIS) | 좌표 유지, 겹치는 사진 중복 라벨 불필요, 면적 직접 | 정사영상이 먼저 필요, 식생 경계가 블렌딩됨 | 사이트 단위 본 라벨링 |
| 모델 예측 → 사람 수정 (active learning) | 2회차부터 속도 5~10배 | 초기 모델 필요 | 2차 이후 |

## 권장 파이프라인
1. 정사영상 생성(PPK 후) → QGIS나 CVAT에 올린다. → [[정사영상]], [[RTK와 PPK]]
2. SAM 프롬프트 + 시드 기반 반자동으로 초벌 마스크.
3. 도메인 전문가가 클래스 이름 확정·오류 수정(폴리곤 편집).
4. 마스크 PNG(+GeoTIFF) 저장. 클래스 정의 문서와 함께 버전 관리.
5. 초벌 모델 학습 → 예측을 다음 배치 초벌로 사용(active learning).

## 클래스 정의 원칙
- 사진에서 사람이 일관되게 구분할 수 있는 단위로. 종이 애매하면 「형태 클래스」(밀생 녹색 / 성긴 식생 / 고사)로 먼저 라벨하고 종 이름은 현장 확인 후 매핑.
- 경계·비네팅·애매한 픽셀은 255(무시).
- 클래스별 최소 픽셀 수·이미지 수를 확보한다. 한 이미지에만 있는 클래스는 검증할 수 없다.

## 예: 특징 기반 반자동 라벨링 순서
DINOv2 ViT-S/14 패치 특징(PCA 48차원) + 색도·ExG·밝기·국소분산
→ 이미지당 시드 박스 1~5개로 로지스틱 회귀
→ 전 패치 예측
→ SLIC 슈퍼픽셀로 경계 정리
→ 원본 크기로 업샘플.
GPU로 10장 남짓이 1분 안팎이다.

## 폴리곤 vs 브러시: 덮인 면적 비율이 목적일 때
- 목적이 **덮인 면적 비율(피복률)**이면 폴리곤은 맞지 않다. 폴리곤은 군락 안 빈 틈까지 대상으로 센다. 경계를 정밀하게 그려도 같다. 표현 방식 자체의 한계다.
- 군락 범위(외곽 면적)만 필요하면 폴리곤으로 충분하다.
- 픽셀(브러시) 라벨에서 군락 폴리곤은 자동으로 만들 수 있다(틈 메우기 후 외곽선 추출). 반대는 안 된다. 그래서 브러시가 상위 호환이다.
- 브러시가 「느리다」는 단점은 고해상도 원본 사진 + 모델 자동 초안을 붙이면 크게 줄어든다.
